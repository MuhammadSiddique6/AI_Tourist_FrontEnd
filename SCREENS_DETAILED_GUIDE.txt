SCREEN 1: LOGIN SCREEN
================================================================================

FILE: src/screens/LoginScreen.tsx
PURPOSE: Allow existing users to sign in with email and password

┌─────────────────────────────────────┐
│  AI-Based Tourist Companion         │
│  Cultural awareness, in your pocket │
├─────────────────────────────────────┤
│  Welcome back                       │
│  [Email input field]                │
│  [Password input field]             │
│  Forgot password? (link)            │
│  [Sign in button]                   │
│  New here? Create an account (link) │
└─────────────────────────────────────┘

STEP-BY-STEP FLOW:

1. USER ENTERS EMAIL
   - Text input field labeled "Email"
   - Keyboard type: email-address
   - Auto-capitalization: OFF
   - Auto-complete: enabled
   
2. USER ENTERS PASSWORD
   - Text input field labeled "Password"
   - Masked (dots instead of characters)
   - Auto-focus set to move from email to password
   - Return key triggers submission

3. USER TAPS "SIGN IN" BUTTON
   Step A: Input Validation
   - Checks if email is valid format (contains @ and .)
   - Checks if password is at least 6 characters
   - If errors found: Display error messages next to fields
   - If valid: Continue to step B

   Step B: API Call
   - Sends POST request to /auth/login
   - Body contains: { email, password }
   - Shows loading spinner while waiting
   - Timeout: 15 seconds

   Step C: Response Handling
   - If successful (200 OK):
     * Backend returns: { token, user }
     * token = JWT authentication token
     * user = User object with id, email, displayName, role
     * Calls login() function from AuthContext
     * User data and token stored in context
     * Navigates to Home Screen
   
   - If failed (400, 401, 500):
     * Shows error message: "Login failed" or server message
     * Error displayed under password field
     * User can try again

4. ERROR CLEARING
   - When user starts typing to fix error
   - Error message disappears automatically
   - Happens for both email and password fields

5. FORGOT PASSWORD LINK
   - Tapping "Forgot password?" navigates to ForgotPasswordScreen
   - Takes user through password reset flow

6. CREATE ACCOUNT LINK
   - Tapping "Create an account" navigates to RegisterScreen
   - New users go through registration process

KEY COMPONENTS:
- AppLogo: Shows app logo at top
- ScreenBackground: Sets gradient/color background
- TextField: Custom input component with error handling
- PrimaryButton: Main action button with loading state
- KeyboardAvoidingView: Keeps inputs visible when keyboard opens
- SafeAreaView: Respects device notches/safe area

KEYBOARD HANDLING:
- iOS: Padding offset to avoid keyboard
- Android: Height adjustment
- keyboardShouldPersistTaps: "handled" (allows tapping non-input areas)
- keyboardDismissMode: "on-drag" (dismiss when scrolling)

STATE VARIABLES:
- email: string (current email input)
- password: string (current password input)
- errors: object (validation errors for each field)
- submitting: boolean (true while API request in progress)

│  [Email input]                      │
│  [Password input]                   │

└─────────────────────────────────────┘

STEP-BY-STEP FLOW:

1. USER ENTERS DISPLAY NAME
   - Text field for user's name (e.g., "Ahmed Khan")
   - Used for personalization throughout the app
   - Auto-complete: name
   - Must be at least 2 characters

2. USER ENTERS EMAIL
   - Same as login screen
   - Must be valid email format

3. USER ENTERS PASSWORD
   - Same as login screen
   - Must be at least 6 characters

4. USER TAPS "REGISTER" BUTTON
   Step A: Input Validation
   - Validates all three fields
   - displayName: not empty, at least 2 chars
   - email: valid format
   - password: at least 6 characters
   - Shows error messages if validation fails

   Step B: Register API Call
   - Sends POST to /auth/register
   - Body: { name: displayName, email, password }
   - Backend creates new user account
   - Returns user ID

   Step C: Auto-login
   - Immediately calls /auth/login API
   - With same email and password
   - Gets authentication token
   - User doesn't need to manually sign in

   Step D: Session Created
   - login() called with user data and token
   - Context stores user session
   - Navigates to Home Screen

5. ERROR HANDLING
   - If email already exists: shows error
   - If server fails: shows server message
   - User can correct and try again

6. BACK BUTTON
   - Returns to Login screen
   - Discards form data

KEY DIFFERENCES FROM LOGIN:
- Three fields instead of two
- Auto-login after registration
- Tab navigation between fields
- "Back to sign in" instead of "Forgot password"

FIELD PROGRESSION:
displayName → Email → Password → Register
(Each field's return key focuses next field)

================================================================================

FILE: src/screens/OtpVerificationScreen.tsx
PURPOSE: Verify the 6-digit code sent to email

┌─────────────────────────────────────┐
│  ← Use a different email            │

│  Resend code to email (link)        │
└─────────────────────────────────────┘

STEP-BY-STEP FLOW:

1. USER ENTERS 6-DIGIT CODE
   - Input field accepts only numbers
   - Auto-stops at 6 digits
   - Displays as the user types
   - Example: User types "1", "2", "3", etc.

2. USER TAPS "VERIFY AND CONTINUE"
   Step A: Validation
   - Checks that code is exactly 6 digits
   - Shows error if format wrong

   Step B: Verify OTP
   - Calls verification function
   - Checks if code matches the one sent to email
   - Checks if code hasn't expired (usually 10-15 min)

   Step C: Success
   - If valid: Navigates to Reset Password screen
   - Passes: email, otp_code (as route params)

   Step D: Failure
   - If invalid: Shows error "Invalid or expired code"
   - User can try again or resend

3. RESEND CODE
   - User taps "Resend code to email"
   - Calls resend API
   - Generates new code
   - Sends to same email
   - Shows alert with new code (in demo)

4. BACK BUTTON
   - "Use a different email" link
   - Returns to Forgot Password
   - Allows entering different email

KEY VALIDATION:
- Must be exactly 6 digits
- Cannot be empty
- Time-based expiration

SCREEN 5: RESET PASSWORD SCREEN
================================================================================

FILE: src/screens/ResetPasswordScreen.tsx
PURPOSE: Set a new password after OTP verification

┌─────────────────────────────────────┐
│  ← Back to code                     │
│  (App Logo)                         │
│  Create new password                │
│  Choose a strong password for email │
├─────────────────────────────────────┤
│  [New password input]               │
│  [Confirm new password input]       │
│  [Update password button]           │
└─────────────────────────────────────┘

STEP-BY-STEP FLOW:

1. SESSION VALIDATION
   - On screen load, checks if otp_code exists
   - If missing (expired session): Shows alert
   - Returns user to Forgot Password screen
   - Prevents unauthorized password resets

2. USER ENTERS NEW PASSWORD
   - First password field
   - Masked display
   - Must be at least 6 characters
   - Should be strong (recommendation: mix of chars)

3. USER CONFIRMS PASSWORD
   - Second password field
   - Must match first password
   - If they don't match: Shows error

4. USER TAPS "UPDATE PASSWORD"
   Step A: Validation
   - Checks both passwords not empty
   - Checks both passwords are at least 6 chars
   - Checks both passwords match exactly

   Step B: Update Password API
   - Calls /auth/reset-password
   - Sends: { email, otp_code, password }
   - Backend updates password in database

   Step C: Success
   - Resets navigation stack
   - Navigates to Login Screen
   - Shows alert: "Password updated successfully"
   - User can now login with new password

5. ERROR HANDLING
   - Passwords don't match: Shows error
   - Password too short: Shows error
   - Backend error: Shows server message
   - Network error: Shows timeout

SECURITY FEATURES:
- OTP_code required (can't reset without it)
- Password field masked
- Timeout prevents old sessions from working
- Backend validates before updating

COMPLETE PASSWORD RESET FLOW:
1. Forgot Password (enter email)
2. OTP Verification (enter code from email)
3. Reset Password (enter new password)
4. Login Screen (sign in with new password)

STEP-BY-STEP FLOW:

1. PERMISSION CHECK
   - App requests camera permission on first use
   - If denied: Shows permission request screen
   - If granted: Shows camera feed

2. CAMERA SETUP
   - Live video stream from device camera
   - Fixed camera direction: back (facing outward)
   - Dark overlay on sides with bright scan frame
   - Status pill at top shows location status
   - Pulsing scanner overlay guides user

3. USER TAPS SHUTTER BUTTON
   - Circular button at bottom center
   - When pressed: Expands outer ring animation
   - Captures photo from camera

4. PHOTO PROCESSING
   - Shows loading spinner
   - Pulsing scale animation
   - Text: "Recognizing landmark…"
   - Sends to backend ML model
   - Timeout: 2 minutes (models can be slow)

5. RECOGNITION RESULT
   
   IF LANDMARK FOUND:
   - ResultCard appears in bottom area
   - Shows recognized landmark details:
     * Name
     * Category
     * Distance from user
     * Confidence percentage (95%)

     * "سنیں · اردو": Text-to-speech in Urdu

     * "Details" button opens full Detail Screen

   - Alert shows: "Detected '[landmark name]' but not in database"
   - Shows confidence percentage
   - User can go back and try another photo
   
   IF NO LANDMARK DETECTED:
   - Alert: "Could not recognize the landmark"
   - User can try again with different angle/lighting

6. RESULT CARD INTERACTIONS:
   
   Listen English:
   - Plays audio pronunciation in English
   - Also plays text description as TTS
   
   Listen Urdu:
   - Same but in Urdu language
   - Uses Urdu text-to-speech voice
   
   Translate:
   - Opens modal with English and Urdu side-by-side
   - Full paragraph translations visible
   - Can read bilingual content
   
   Save:
   - Adds landmark to SavedLandmarksContext
   - Shows confirmation: "[Landmark] added to collection"
   
   Details:
   - Navigates to Detail Screen
   - Shows full information about landmark
   - Can view 3D models, more history, etc.

7. RETAKE PHOTO
   - Tap shutter again to take another photo
   - Replaces previous result
   - Result card updates with new recognition

8. ERROR HANDLING:
   - Camera permission denied: Shows request
   - Photo cancelled: Returns to camera
   - Network error: Shows alert with message
   - Timeout: Shows "Request timed out" message
   - Server error: Shows server error message

KEY FEATURES:
- On-device demo mode (offline ready)
- ML model runs on backend
- Real-time camera preview
- Immediate results
- Bilingual support
- Save to collection
- Works offline with cached data

TECHNICAL DETAILS:
- CameraView: expo-camera component
- Image capture: expo-image-picker
- API: POST /ai/recognize with FormData
- Timeout: 120 seconds for ML model
- Result includes: prediction, confidence, landmark data

1. ACCESS CONTROL
   - Only visible to users with role: "admin"
   - Called from Profile Screen
   - Requires admin authentication

2. DATA LOADING
   - Calls fetchAdminUsers() API
   - Gets all users from backend
   - Sets loading state = true
   - Shows spinner while loading
   - Handles errors gracefully

3. PULL-TO-REFRESH
   - User can pull down to refresh list
   - Calls loadUsers(isRefresh: true)
   - Shows refresh indicator
   - Re-fetches data from backend
   - Updates list with new data

4. USER LIST (FlatList)
   - Displays all users as cards
   - Each card shows user information:
     * Avatar: Circle with first letter
     * Name
     * Email
     * Role: "admin" or "user"
     * Verification status: "Verified" or "Unverified"

   - If user viewing is same as card user:
     * Shows "You" badge
     * Highlighted differently

   BLOCK USER:
   - Shows confirmation alert:
     * "Block user?"
     * "[Name] will not be able to sign in"
     * Cancel or Block button
   - Calls setUserBlocked(userId, true)
   - Prevents user from logging in
   - User card updates immediately
   - Shows "Blocked" status

   UNBLOCK USER:
   - Shows confirmation alert:
     * "Unblock user?"
     * "[Name] will be able to use the app again"
   - Calls setUserBlocked(userId, false)
   - User can login again
   - User card updates immediately
   - Status changes to "Active"

     * "Delete user?"
     * "Permanently remove [name] ([email])?"
     * "This cannot be undone"
     * Cancel or Delete button
   - Calls deleteAdminUser(userId)
   - User completely removed from database
   - Card disappears from list
   - Action cannot be undone

7. ACTION FEEDBACK:
   - Shows loading indicator on user card
   - Disables action buttons during request
   - Shows error alert if action fails
   - Reverts if error occurs

   - Error recovery
   - Toast/alert feedback

NAVIGATION HIERARCHY
================================================================================

COMPLETE NAVIGATION TREE:

┌─ APP
   ├─ AuthStack (before login)
   │  ├─ Login Screen
   │  ├─ Register Screen
   │  ├─ Forgot Password Screen
   │  ├─ OTP Verification Screen
   │  └─ Reset Password Screen
   │
   └─ MainStack (after login)
      ├─ MainTabNavigator (bottom tab bar)
      │  ├─ Home Tab → Home Screen
      │  ├─ Scan Tab → Scan Screen
      │  ├─ Map Tab → Map Screen
      │  └─ Profile Tab → Profile Screen
      │
      └─ Nested Stack (modal/full screens)
         ├─ Detail Screen (from Home/Map/Scan/Profile)
         ├─ Model3DViewer (from Detail)
         ├─ Landmark3DImage (from Detail)
         └─ AdminUsers (from Profile - admin only)

NAVIGATION FLOW EXAMPLES:

FIRST TIME USER:
1. App Opens → AuthStack visible
2. Login Screen (default)
3. Tap "Create an account" → Register Screen
4. Fill form → Tap "Register"
5. Auto-login → Navigates to Home Screen
6. MainTabs visible (Home/Scan/Map/Profile)

EXISTING USER:
1. App Opens → AuthStack visible
2. Login Screen (default)
3. Enter email/password → Tap "Sign in"
4. Successful → Navigates to Home Screen
5. MainTabs visible

FORGOT PASSWORD:
1. Login Screen
2. Tap "Forgot password?" → Forgot Password Screen
3. Enter email → Send code
4. → OTP Verification Screen (via alert)
5. Enter code → Verify
6. → Reset Password Screen
7. Enter new password → Update
8. → Login Screen (resets stack)

SCANNING LANDMARK:
1. Home Screen
2. Tap "Scan" card → Scan Screen (Tab 2)
3. Take photo → Recognition
4. → Detail Screen (if successful)
5. Can go back to Scan or navigate to other tabs

EXPLORING LANDMARK:
1. Home Screen
2. Tap "Map" card → Map Screen (Tab 3)
3. Tap landmark marker → Detail Screen
4. View info → Optional 3D Model or 3D Image
5. Can go back to Map or other tabs

PROFILE/SAVED:
1. Any screen → Tap Profile Tab → Profile Screen
2. View saved landmarks
3. Tap landmark → Detail Screen
4. Tap trash → Remove from saved
5. Tap "Sign out" → AuthStack (back to Login)

ADMIN PANEL:
1. Profile Screen (as admin user)
2. Tap "Admin panel" card → Admin Users Screen
3. View all users
4. Block/Delete users
5. Back arrow → Returns to Profile
