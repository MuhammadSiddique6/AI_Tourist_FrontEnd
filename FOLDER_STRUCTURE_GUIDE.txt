ROOT LEVEL FILES:
================================================================================

app.json
├─ PURPOSE: Expo configuration file
├─ CONTAINS: App name, version, icons, permissions, Android/iOS settings
├─ KEEP: YES - Essential for the app to run
├─ MODIFIED: No need to change unless updating permissions or app info

App.tsx
├─ PURPOSE: Main entry point of the React Native application
├─ CONTAINS: Root component that loads authentication or main app navigator
├─ KEEP: YES - Required entry point
├─ MODIFIED: No, this is good

babel.config.js
├─ PURPOSE: Babel configuration for transpiling JavaScript/TypeScript
├─ CONTAINS: Plugin configuration for React Native and Metro bundler
├─ KEEP: YES - Required for build process
├─ MODIFIED: No, standard Expo configuration

eslint.config.js
├─ PURPOSE: ESLint configuration for code quality and style
├─ CONTAINS: Rules for code formatting and error detection
├─ KEEP: YES - Helps maintain code quality
├─ MODIFIED: Can add more rules if needed

metro.config.js
├─ PURPOSE: Metro bundler configuration (React Native build tool)
├─ CONTAINS: Asset handling, extraNodeModules, watch folders
├─ KEEP: YES - Required for development server
├─ MODIFIED: No, standard configuration

package.json
├─ PURPOSE: Node package manager configuration
├─ CONTAINS: Dependencies, dev dependencies, scripts, project metadata
├─ KEEP: YES - Essential for npm/yarn
├─ MODIFIED: Only when adding/removing dependencies

package-lock.json
├─ PURPOSE: Locks specific versions of dependencies
├─ CONTAINS: Exact versions of all installed packages
├─ KEEP: YES - Ensures consistent installations
├─ MODIFIED: Auto-updated by npm

tsconfig.json
├─ PURPOSE: TypeScript configuration
├─ CONTAINS: Compiler options, strict mode, path aliases
├─ KEEP: YES - Required for TypeScript support
├─ MODIFIED: No, good configuration

README.md
├─ PURPOSE: Project documentation and setup instructions
├─ CONTAINS: How to run, features, deployment info
├─ KEEP: YES - Important for project documentation
├─ MODIFIED: Yes, should be updated with latest features

test-login.json
├─ PURPOSE: Test credentials for development/testing
├─ CONTAINS: Sample login email and password for testing
├─ KEEP: YES - Useful for testing but should not be committed
├─ MODIFY: Add to .gitignore to prevent accidental commit
├─ NOTE: Make sure real credentials are never in this file

================================================================================
FOLDER PURPOSES - DETAILED BREAKDOWN
================================================================================

src/components/
─────────────────
PURPOSE: Reusable UI building blocks used across multiple screens
CONTAINS: Buttons, input fields, cards, overlays, modals
ORGANIZED: By functionality (not by screen)
BENEFIT: Update a component once, all screens using it update automatically

src/constants/
──────────────
PURPOSE: Fixed data that doesn't change during app runtime
CONTAINS: Colors/theme, landmark coordinates, images, categories
USAGE: Imported by components and screens
BENEFIT: Centralized configuration - easy to update global settings

src/context/
────────────
PURPOSE: Global state management (user data, saved items)
CONTAINS: AuthContext (who's logged in), SavedLandmarksContext (favorites)
USAGE: Used with useContext() hooks throughout the app
BENEFIT: User data available in any screen without prop drilling

src/hooks/
──────────
PURPOSE: Reusable logic that can be shared between screens
CONTAINS: Fetch data, get location, handle translations
PATTERN: Custom React hooks starting with "use"
BENEFIT: Keep screens clean, extract complex logic

src/navigation/
───────────────
PURPOSE: Define which screens exist and how to navigate between them
CONTAINS: Stack navigators, tab navigators, route configuration
STRUCTURE: 
  - AuthStackNavigator: Login → Register → Forgot → OTP → Reset
  - MainTabNavigator: Home, Scan, Map, Profile tabs
  - AppNavigator: Combines auth + main navigation
BENEFIT: Centralized routing logic

src/screens/
────────────
PURPOSE: Individual page/screen components
ONE SCREEN = ONE FILE (mostly)
COUNT: 13 different screens
NAMING: Matches what appears on device (LoginScreen, HomeScreen, etc.)

src/services/
─────────────
PURPOSE: Backend communication and business logic
CONTAINS: 
  - API calls to server
  - Mock/demo data for offline mode
  - Validation functions
  - Form processing
SEPARATION: Keeps screens clean, logic in services
BENEFIT: Easy to test, easy to switch backends

src/types/
──────────
PURPOSE: TypeScript type definitions
USED FOR: Type safety, autocomplete, error detection
CONTAINS: Interfaces for User, Landmark, Hotel, etc.
BENEFIT: Catch errors at development time, not runtime

src/utils/
──────────
PURPOSE: Small utility functions
CONTAINS: Math calculations, helper functions
EXAMPLES: Distance formatting, 3D model loading
